# 1 项目研究进展和任务完成情况

本项目在中期阶段最核心的变化，是研究目标已经由前期的“加密流量业务类型分类”正式转向“加密方法识别”。前期工作中，项目主要关注 `BROWSING`、`CHAT`、`FT`、`MAIL`、`P2P`、`STREAMING`、`VOIP` 等业务语义类别，这一阶段的实验为后续提供了特征工程、模型训练、结果分析和文档组织经验。但在导师提出“要识别流量采用何种加密方法”的要求后，项目组对研究问题、标签体系、数据来源和模型输出口径进行了重构。本阶段的正式任务不再回答“用户在做什么业务”，而是回答“该流量采用了什么样的可见加密协议、加密传输机制或匿名通信方式”。因此，中期报告主要围绕转型后的主线展开，前期业务分类实验只作为技术储备和路线演化背景，不再作为本阶段核心成果。

从研究问题的重新定义来看，本项目当前采用的是“可见加密机制识别”的口径，而不是直接识别底层密码算法。原因在于，真实网络流量中底层密码套件往往只在握手阶段有限可见，而课程项目可稳定落地的数据资源更适合支撑协议级、隧道级和匿名通信机制级别的识别研究。基于现有数据条件和工程可行性，项目将最终标签空间统一为 `NON_ENCRYPTED`、`TLS_FAMILY`、`SSH`、`QUIC`、`VPN`、`TOR`、`I2P`、`FREENET`、`ZERONET` 九类。其中 `TLS_FAMILY` 代表 TLS/SSL/DTLS 等可归并的主流加密传输族，`VPN` 代表显式虚拟专用网络类流量，`TOR/I2P/FREENET/ZERONET` 代表不同匿名或暗网通信机制，`NON_ENCRYPTED` 则作为对照类别保留。这样的标签设计既符合“识别加密方法”的研究表达，又能够让多源公开数据在统一框架下参与训练。

围绕这一目标，项目首先完成了数据资源的重新梳理与统一。与前期单一数据集建模不同，本阶段明确要求使用 `data/` 目录下所有能够服务于新任务的数据源，并且不能继续依赖旧的业务分类训练脚本。为此，项目重新设计了从原始数据到统一数据集的构建链路。当前实际纳入的新任务数据源包括 `data/Dataset.csv`、`data/BCCC-Darknet-2025 (6)(1)/Binary -2DSCombined.csv`、`data/BCCC-Darknet-2025 (6)(1)/MultiTotalDS.csv`、`data/encryption_method_identification/flow_features_all.csv`、`data/encryption_method_identification/flow_features_labeled.csv`，以及用户特别强调必须使用的 `data/Tor/Tor` 和 `data/NonTor/NonTor` 原始抓包数据。对于 `Tor.zip`、`NonTor.tar.xz`、`NonVPN-PCAPs-01.zip`、`NonVPN-PCAPs-03.zip`、`VPN-PCAPs-02.zip` 等压缩包，项目遵循“不重复统计同一批数据”的原则，仅保留解压后的等价原始内容或已经抽取得到的结构化结果参与训练。

为支撑这种多源异构数据融合，项目在 `src/encryption_method/` 目录下从零编写了新的数据构建脚本和训练脚本，而不是复用旧脚本。新的 `build_unified_dataset.py` 负责把多种 CSV 和 PCAP/PCAPNG 数据源映射到统一特征空间；新的 `train_hybrid_classifier.py` 则负责完成层级式深度学习训练。对原始抓包部分，脚本通过 `tshark` 解析包级字段，将原始数据聚合为双向五元组流，提取持续时间、包数、字节数、前后向比例、包长统计量、包间隔统计量、加密提示比例等 `21` 个共用数值特征，同时生成用于序列建模的 `sequence_text` token 序列。这样，转型后的主线不仅保留了表格化统计信息，还额外引入了来自原始抓包的行为序列表示，使模型能够在“结构化特征 + 轻量序列分支”的框架下学习更稳定的判别模式。

在统一数据集构建方面，项目已经形成了较完整的阶段性成果。当前生成的二分类预训练数据集 `binary_pretrain.csv` 共 `534989` 条样本，用于学习“加密”与“非加密”的粗粒度区分；多分类微调数据集 `multiclass_finetune.csv` 共 `316601` 条样本，用于识别具体加密方法类别。多源数据的纳入情况如下表所示：

| 数据源 | 纳入方式 | 当前纳入量 |
| --- | --- | --- |
| `Dataset.csv` | 直接映射到统一标签空间 | `239176` 条 |
| `BCCC Binary` | 参与二分类预训练，并对可映射部分参与多分类 | 二分类 `25538` 条，多分类 `18570` 条 |
| `BCCC Multi` | 直接映射到统一多分类标签 | `7921` 条 |

| `data/Tor/Tor` 原始抓包 | 使用 `tshark` 重新抽取流并标注 | `136` 条 |

从模型路线看，本阶段已经不再沿用早期以单一表格分类器为核心的方案，而是构建了一个新的层级式深度学习模型。模型分为两个阶段：第一阶段先用全部可用样本学习 `ENCRYPTED` 与 `NON_ENCRYPTED` 的二分类；第二阶段再用仅包含加密流量的样本学习 `TLS_FAMILY`、`SSH`、`QUIC`、`VPN`、`TOR`、`I2P`、`FREENET`、`ZERONET` 八类加密方法。推理时先通过二分类模型判断一条流是否加密，如果判断为非加密则直接输出 `NON_ENCRYPTED`，如果判断为加密则交由第二阶段模型做细粒度识别。单个模型内部又采用了数值特征分支、数据源嵌入分支、传输层协议嵌入分支和序列卷积分支的混合结构。这种设计的目的，一方面是利用统一数值特征保证模型在多源数据上的稳定性，另一方面是让来自原始抓包的时序 token 能在不引入超大预训练模型的情况下提供额外的判别信息。

为了进一步提升转型后主线的少数类表现，项目在中期阶段又对多分类训练策略进行了修正。初版全量训练虽然整体精度较高，但对极少数类采用了过强的反频率补偿，导致 `FREENET` 等极小类被过度放大，整体宏平均指标受到影响。针对这一问题，项目重新调整了训练脚本，将多分类阶段的采样权重和损失函数类别权重改为“平滑反频率”形式，即不再机械使用 `1 / class_count`，而是采用温和幂次补偿策略。该改动保留了少数类的可见性，同时减轻了过度偏向极小类带来的副作用，构成了中期阶段最重要的一次模型优化。

# 2 研究取得的成果

转型后的第一项重要成果，是项目已经形成了一套可直接服务于“加密方法识别”任务的统一数据体系。与前期只能在业务分类语境下讨论模型优劣不同，当前数据集已经能够明确支撑“识别可见加密机制”的研究表达。新的数据集不再依赖单一来源，而是把历史积累的结构化流量数据、已有的加密方法标注数据，以及 `Tor`、`NonTor` 原始抓包数据统一纳入同一框架中。这意味着项目已经从“有一些可用实验材料”推进到“具备系统化研究数据底座”的阶段。尤其值得指出的是，`data/Tor/Tor` 与 `data/NonTor/NonTor` 在此前并没有被完整纳入主线实验，而中期阶段已经通过重新编写脚本和引入 `tshark` 原始解析的方式将其并入统一数据集，这使项目在“匿名通信机制识别”上具有了更真实的实验基础。

第二项成果，是围绕新任务已经建立起一条完整的深度学习工程链路。当前仓库中与转型后主线直接对应的核心文件已经包括 `src/encryption_method/build_unified_dataset.py`、`src/encryption_method/train_hybrid_classifier.py`、`data/unified_encryption_method_v2_all_data/` 和 `outputs/encryption_method/hybrid_unified_v4_tempered_all_data/`。其中，数据目录下已经包含 `binary_pretrain.csv`、`multiclass_finetune.csv`、`raw_tor_flows.csv`、`raw_nontor_flows.csv` 和 `metadata.json` 等统一产物；输出目录下则包含 `metrics.json`、分类报告、混淆矩阵、按来源统计的指标、预测结果和最终模型权重。换言之，项目已经不再停留在“临时跑通一个实验”的层面，而是具备了“可重复构建数据、可重复训练模型、可重复导出结果”的标准化能力，这一点对后续结题报告、答辩展示和实验复查都具有直接价值。

第三项成果，是转型后主线已经取得了可用于中期答辩的阶段性实验结果。在当前最优的 `hybrid_unified_v4_tempered_all_data` 实验中，二分类预训练阶段的测试集 `Accuracy` 达到 `0.9898`，`Macro-F1` 达到 `0.9898`；加密流量内部的多分类微调阶段测试集 `Accuracy` 达到 `0.9755`，`Macro-F1` 达到 `0.7576`；最终层级式整体测试结果 `Accuracy` 达到 `0.9866`，`Macro-F1` 达到 `0.7790`，`Weighted-F1` 达到 `0.9882`。相关核心指标如下表所示：

| 指标项 | 当前结果 |
| --- | --- |
| 二分类测试 `Accuracy` | `0.9898` |
| 二分类测试 `Macro-F1` | `0.9898` |
| 加密多分类测试 `Accuracy` | `0.9755` |
| 加密多分类测试 `Macro-F1` | `0.7576` |
| 最终层级测试 `Accuracy` | `0.9866` |

如果从持续优化的角度来看，本阶段还有一个比较清楚的结论：经过新的平滑类别补偿训练策略调整后，转型后主线的整体宏平均指标继续提升。与前一版全量训练结果相比，最终层级测试的 `Macro-F1` 已经由 `0.7431` 提升到 `0.7790`，提升幅度为 `0.0359`；加密多分类阶段 `Macro-F1` 也由 `0.7192` 提升到 `0.7576`。这说明中期阶段的优化不是停留在“完成转型”本身，而是在转型完成之后已经进入了第二轮针对弱类和训练策略的有效收敛。

从类别级结果看，当前模型对主流加密方法已经表现出较好的识别能力。`TLS_FAMILY` 召回率达到 `0.9927`，`SSH` 达到 `0.9980`，`QUIC` 达到 `1.0000`，`VPN` 达到 `0.9798`，这表明项目在可见主流加密协议和隧道类流量识别方面已经取得了较稳定的结果。同时，`I2P` 和 `ZERONET` 的召回率也分别达到 `0.6635` 和 `0.7622`，说明模型对较弱的匿名通信机制已经具备一定识别能力。尽管 `TOR` 的召回率目前仍只有 `0.4095`，但其精确率已经达到 `0.7350`，这意味着模型已经学到了较有区分度的 `TOR` 模式，只是样本量不足导致覆盖面不够，这为后续补强提供了明确方向。

第四项成果，是项目对多源数据质量和跨源表现已经形成了初步认识。按数据来源统计，`DATASET_CSV` 的测试准确率达到 `0.9985`、宏平均 `F1` 达到 `0.9974`；`FLOW_LABELED` 达到 `0.9861 / 0.8835`；`RAW_NONTOR` 达到 `0.9997 / 0.9997`。这些结果说明，对于标签较稳定、映射关系较清晰或结构较规整的数据，当前模型已经具备非常强的判别能力。与此同时，`BCCC_MULTI` 的测试准确率只有 `0.5929`，宏平均 `F1` 为 `0.5276`，这暴露出跨来源标签语义不完全一致的问题。项目组据此已经形成一个重要认识：转型后的主线虽然已经跑通，但其真正难点不再是“模型能不能收敛”，而是“跨源异构标签如何被稳定地统一表达”。这种认识本身就是中期阶段有价值的研究产出，因为它帮助项目把后续优化焦点从泛泛调参收敛到了数据语义一致性与弱类增强上。

第五项成果，是项目已经能够围绕转型后任务形成较清晰的阶段性结论。当前结果表明，以统一数值特征为主体、辅以轻量时序 token 分支的层级深度学习方案，在现有数据条件下是可行的；把所有可用数据源统一纳入训练，特别是把 `Tor/NonTor` 原始抓包重新接入主线，是有实际收益的；在强类别不平衡条件下，单纯使用激进反频率补偿并非最优，而适度平滑的类别补偿更能兼顾整体宏平均表现和少数类稳定性。这些结论都已经超出了“只是把项目方向换个名字”的层面，说明转型后的主线已经具备真实的实验基础和可写入正式报告的研究内容。

# 3 研究存在的问题

尽管转型后的主线已经取得了比较明确的进展，但从研究质量和结题要求来看，当前仍然存在若干关键问题。首先，`TOR` 类数据明显不足，仍是限制整体宏平均指标进一步提升的首要瓶颈。虽然 `data/Tor/Tor` 已经被正式纳入统一数据集，但在现有较保守的过滤规则下，真正进入训练的数据只有 `136` 条，测试集仅有 `21` 条原始 `RAW_TOR` 样本。这一数量对于训练稳定的匿名通信机制识别模型显然偏少，也直接导致当前 `TOR` 的召回率只有 `0.4095`。从现有分析来看，模型并不是完全学不到 `TOR` 模式，而是对 `TOR` 流的覆盖不够充分。因此，后续需要针对原始 `TOR` 长流做窗口化切分、过滤规则放宽或补充受控抓包，以真正提高 `TOR` 类的训练规模。

第二，当前多源数据之间仍存在较明显的分布差异和标签语义差异。虽然统一标签空间已经建立起来，但不同来源的数据原本服务的任务并不完全相同，有些来源原始上更偏向业务分类、暗网流量区分或协议识别，因此它们映射到统一标签后的“纯度”并不一致。这一点在 `BCCC_MULTI` 上已经表现得较为明显，其测试指标显著低于 `DATASET_CSV` 和 `RAW_NONTOR`。这说明项目虽然已经完成了“数据都并进来”的工程目标，但“并进来以后语义是否完全对齐”仍是一个研究问题。后续必须通过更细致的误分类分析、来源对照和必要的标签再审查，确认当前统一标签体系的可靠边界。

第三，类别极不平衡问题仍然客观存在，尤其是 `FREENET`、`I2P`、`ZERONET`、`TOR` 这类相对少样本类别。当前模型经过平滑补偿后，`FREENET` 的召回率已经达到 `0.9583`，但精确率只有 `0.0996`，这说明模型虽然能够覆盖该类样本，但同时也把其他类别过多地吸引到了 `FREENET` 上。类似地，`TOR`、`I2P` 和 `ZERONET` 之间也仍有明显混淆。这表明现阶段的问题不再只是“有没有考虑类别不平衡”，而是“怎样在少样本类别之间建立更清晰的判别边界”。如果这一问题不解决，最终报告中虽然可以展示较高总体准确率，但在安全研究更看重的弱类可靠识别上仍然显得不够扎实。

第四，当前任务所说的“加密方法识别”仍然是一个经过工程化定义后的研究口径，而不是底层密码算法级别的严格识别。也就是说，项目现在识别的是“可见协议族、可见隧道机制和匿名通信机制”，而不是直接识别 `AES-GCM`、`ChaCha20-Poly1305` 或某个精确握手套件。这一口径本身是合理的，也是当前公开数据条件下更可落地的选择，但在中后期报告和答辩中必须准确说明这一边界，避免把结论外推成“本项目已经能识别所有具体密码学实现”。只有把任务边界说清楚，项目的研究表述才是严谨的。

第五，虽然新的工程链路已经跑通，但实验规范性仍有继续加强的空间。当前统一数据集采用了统一随机划分和分层策略，这对于课程项目中期阶段已经足够支撑可复现实验，但如果要进一步提升研究说服力，后续仍建议补充按抓包文件、按来源甚至按采集批次划分的泛化验证。同时，原始抓包解析本身耗时较长，`Tor/NonTor` 全量抽取需要数分钟级别，这也对快速迭代提出了工程挑战。因此，下一阶段不应只围绕模型结构继续扩展，而应同步加强“更严格的划分验证”“更高效的数据重构”和“更清晰的消融设计”，使最终结论不仅分数高，而且可信度高。

除研究内容本身外，本项目在中期阶段已经建立了较规范的资料管理和过程控制方式。当前工作区已按照“原始数据、处理中间数据、模型输出、报告文档、工具脚本”分层组织，其中 `data/` 目录用于保存原始数据和统一数据集，`src/encryption_method/` 用于保存转型后的核心代码，`outputs/encryption_method/` 用于保存模型文件、指标结果和分类报告，`docs/reports/` 用于保存课程文档。这种目录组织方式有助于避免实验脚本、模型结果和报告材料混放，也使后续结题阶段能够直接沿用当前的研究产物，不需要重新整理基础材料。

在实验记录与复现保障方面，项目已经形成了较稳定的输出规范。每次重要训练都会保留 `metrics.json`、分类报告、混淆矩阵、按数据来源统计的结果文件和模型权重，同时在文档中同步记录数据来源、标签体系、训练参数和阶段性结论。与前期只关注单次实验结果不同，转型后的主线更加重视“实验为什么这样设计”“结果由哪些数据支撑”“后续如何复查和继续迭代”。这意味着当前项目不仅是在完成一个模型训练任务，也是在逐步形成一套适合课程验收和后续维护的研究工作流。

从条件保障来看，本项目当前不依赖额外采购设备和专用商业软件，主要使用现有本地计算环境、公开数据集以及 `tshark` 等通用分析工具完成数据构建和模型训练。现阶段的主要资源压力不在于基础环境缺失，而在于原始抓包重建成本较高、少数类样本仍然不足，以及多源标签统一需要持续人工校核。因此，后续阶段的重点不是大规模扩展工具栈，而是在现有环境下继续提高数据质量、增强弱类覆盖并提升结论的解释性。这种条件约束与课程项目周期是匹配的，也说明转型后的研究方案具备继续推进的现实可行性。
