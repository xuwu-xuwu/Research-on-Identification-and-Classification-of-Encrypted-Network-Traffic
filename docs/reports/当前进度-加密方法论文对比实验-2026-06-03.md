# 当前进度：加密方法论文对比实验

更新时间：`2026-06-03`

## 1. 当前研究口径

项目当前主线已经从业务/应用类型分类转向加密方法分类与识别。现有旧复现结果，如 `C-LSTM` 的 `Chat / Email / File Transfer / VPN-*` 和 `TrafficFormer` 的 `Chat / FileTransfer / Streaming / VoIP`，不能直接作为当前主任务的对比实验结果。

当前仓库新增了两层对比框架：

- 第一层：全量 9 类 tabular 主表，对应 `data/unified_encryption_method_v2_all_data/multiclass_finetune.csv`。
- 第二层：面向论文方法的 5 类 PCAP/序列子表，对应 `NON_ENCRYPTED / TLS_FAMILY / SSH / QUIC / TOR`。

## 2. 本次新增代码

### 2.1 第一层全量 tabular 公平基线

已新增：

- `src/encryption_method/unified_benchmark_utils.py`
- `src/encryption_method/benchmark_tabular_baselines.py`

该层用于在同一 9 类任务、同一 `train / valid / test` 划分下训练：

- `RandomForest`
- `ExtraTrees`
- `XGBoost`

该层默认不使用 `source_name`，用于避免数据来源泄漏。

### 2.2 第二层论文方法 PCAP 子表

已新增：

- `src/encryption_method/build_paper_benchmark_dataset.py`
- `src/encryption_method/benchmark_paper_methods.py`

`build_paper_benchmark_dataset.py` 的作用是从真实 PCAP 中重建 5 类加密方法识别子表，并导出三种输入：

- `packet/flows_5class.npz`：包字节输入，供 Deep Packet / TFE-GNN 风格方法使用。
- `trafficformer/*.tsv`：多包 token 序列输入，供 ET-BERT / TrafficFormer 风格方法使用。
- `hybrid/*.csv`：当前项目 hybrid classifier 可直接读取的流级输入。

`benchmark_paper_methods.py` 的作用是在同一个 PCAP 子表上训练三类论文方法本地实现：

- `Deep Packet style CNN`
- `ET-BERT style Transformer`
- `TFE-GNN style GCN`

说明：这是同口径本地实现，不等同于已经完整接入三篇论文官方代码和完整预训练流程。

## 4. 复现命令

### 4.1 构建 5 类 PCAP 子表

```powershell
python src\encryption_method\build_paper_benchmark_dataset.py `
  --max-flows-per-label 40 `
  --max-packets-per-flow 6 `
  --packet-size 256 `
  --max-capture-packets 8000 `
  --max-auto-captures-per-label 4 `
  --output-dir data\paper_benchmark\encryption_method_5class_pcap_v1
```

### 4.2 训练三类论文方法本地实现

```powershell
python src\encryption_method\benchmark_paper_methods.py `
  --data data\paper_benchmark\encryption_method_5class_pcap_v1\packet\flows_5class.npz `
  --output-dir outputs\encryption_method\paper_methods_5class_v1 `
  --epochs 5 `
  --batch-size 16 `
  --models deep_packet_cnn et_bert_transformer tfe_gnn
```

### 4.3 在同一子表上训练当前项目 hybrid 方法

```powershell
python src\encryption_method\train_hybrid_classifier.py `
  --data-dir data\paper_benchmark\encryption_method_5class_pcap_v1\hybrid `
  --output-dir outputs\encryption_method\paper_methods_5class_v1\current_hybrid `
  --binary-epochs 4 `
  --multiclass-epochs 8 `
  --batch-size 32 `
  --hidden-dim 96 `
  --seq-embedding-dim 32 `
  --max-seq-len 64 `
  --early-stop-patience 3
```

## 5. 当前结论

当前结果说明，原始包字节输入在这个 5 类 PCAP 子表上很有优势，`Deep Packet style CNN` 的首轮结果最好。`ET-BERT style Transformer` 已经跑通，但本轮没有接入官方预训练权重，因此只适合作为本地同口径 Transformer 对比。`TFE-GNN style GCN` 目前效果较弱，说明当前紧凑字节转移图实现还不够强，后续应考虑官方图构造流程或更充分的图特征。

当前项目 hybrid 方法仍然更适合第一层全量 tabular 主表；在小规模 PCAP 子表上，由于样本少且层级二阶段误差明显，结果低于 Deep Packet style。

## 6. 后续建议

后续如果要把第二层结果写进最终论文，应继续完成以下工作：

- 扩大 PCAP 子表规模，特别是补充 `QUIC` 和 `TOR`。
- 接入官方 ET-BERT 预训练权重或复用本地 TrafficFormer 预训练权重做严格版本。
- 完善 TFE-GNN 的图构造，避免只使用简化字节转移图。
- 将第一层 9 类全量主表和第二层 5 类 PCAP 子表分开写，避免不同输入粒度的方法被错误放进同一主表比较。

## 7. 当前方法增强进度

基于首轮对比结果，原始 `Current project hybrid` 在第二层 PCAP 子表上表现偏弱：

| method | Accuracy | Macro-F1 | Weighted-F1 |
| --- | ---: | ---: | ---: |
| Original current hybrid | 0.6000 | 0.4067 | 0.6129 |

主要原因是原始方法面向全量 tabular 主表设计，采用二阶段层级分类，且没有直接使用真实包字节。针对这个问题，新增增强版当前方法：

- `src/encryption_method/train_enhanced_pcap_fusion.py`

增强策略：

- 从二阶段层级分类改为单阶段 5 类分类。
- 保留原有流级统计特征。
- 新增全流包字节直方图。
- 新增首包字节序列特征。
- 使用 `ExtraTreesClassifier` 做小样本融合分类。

训练命令：

```powershell
python src\encryption_method\train_enhanced_pcap_fusion.py `
  --packet-data data\paper_benchmark\encryption_method_5class_pcap_v1\packet\flows_5class.npz `
  --hybrid-csv data\paper_benchmark\encryption_method_5class_pcap_v1\hybrid\multiclass_finetune.csv `
  --output-dir outputs\encryption_method\paper_methods_5class_v1\current_pcap_fusion `
  --n-estimators 800
```

增强后结果：

| method | implementation | Accuracy | Macro-F1 | Weighted-F1 |
| --- | --- | ---: | ---: | ---: |
| Enhanced current PCAP fusion | `current_pcap_fusion` | 0.9200 | 0.8846 | 0.9200 |
| Deep Packet style CNN | `deep_packet_cnn` | 0.9200 | 0.8698 | 0.9214 |
| ET-BERT style Transformer | `et_bert_transformer` | 0.7200 | 0.6077 | 0.6585 |
| Original current hybrid | `current_hybrid` | 0.6000 | 0.4067 | 0.6129 |
| TFE-GNN style GCN | `tfe_gnn` | 0.4800 | 0.1371 | 0.3566 |

新增输出：

- `outputs/encryption_method/paper_methods_5class_v1/current_pcap_fusion/metrics.json`
- `outputs/encryption_method/paper_methods_5class_v1/comparison_with_enhanced_current.md`
- `outputs/encryption_method/paper_methods_5class_v1/comparison_with_enhanced_current.csv`

当前增强结论：在第二层 PCAP 子表上，显式融合包字节特征可以显著提升当前方法表现，Macro-F1 从 `0.4067` 提升到 `0.8846`。

## 8. 全量 9 类最新主方法

根据 PCAP 子表增强实验的结论，已经把“融合多粒度证据”的思路迁移到全量 9 类主表。由于全量 `multiclass_finetune.csv` 中大多数样本没有真实包字节，不能直接使用 PCAP byte 分支，因此全量版本采用全量样本都可用或可缺省计算的特征：

- 21 个流级统计特征。
- `transport` one-hot 特征。
- 从 `sequence_text` 派生的 18 个序列统计特征。
- 不使用 `source_name`，避免数据来源泄漏。

新增训练脚本：

- `src/encryption_method/train_full_enhanced_fusion.py`

训练命令：

```powershell
python src\encryption_method\train_full_enhanced_fusion.py `
  --data-dir data\unified_encryption_method_v2_all_data `
  --output-dir outputs\encryption_method\full_enhanced_fusion_v1 `
  --n-estimators 350 `
  --max-depth 7 `
  --learning-rate 0.05 `
  --class-weight-power 0.5
```

输出位置：

- `outputs/encryption_method/full_enhanced_fusion_v1/model.json`
- `outputs/encryption_method/full_enhanced_fusion_v1/model.joblib`
- `outputs/encryption_method/full_enhanced_fusion_v1/metrics.json`
- `outputs/encryption_method/full_enhanced_fusion_v1/comparison.md`

全量 9 类测试结果：

| --- | ---: | ---: | ---: | ---: |
| Full enhanced fusion XGBoost | 0.993978 | 0.892797 | 0.994046 | 0.909893 |

与上一版全量 XGBoost smoke baseline 对比：

| method | Accuracy | Macro-F1 | Weighted-F1 |
| --- | ---: | ---: | ---: |
| XGBoost tabular baseline | 0.993136 | 0.828463 | 0.992758 |

提升：

| metric | improvement |
| --- | ---: |
| Accuracy | +0.000842 |

当前结论：`full_enhanced_fusion_xgboost` 应作为全量 9 类加密方法识别的当前最新主方法；`current_pcap_fusion` 保留为第二层 PCAP/论文方法子表中的增强版当前方法。
