# 1 项目介绍

## 1.1 项目定义

本项目是一个面向离线网络流量分析场景的“加密方法识别”程序系统。系统的核心目标不是识别业务类型，也不是恢复明文内容，而是在不解密载荷的前提下，利用流级统计特征、传输层上下文信息以及由原始抓包抽取得到的轻量序列表示，对网络流量所采用的可见加密协议、隧道机制或匿名通信方式进行自动识别。

从软件形态上看，本系统由两个核心可执行程序组成。第一个程序负责统一数据集构建，即把 `data/` 目录下多个来源、多个格式、多个标签体系的数据资源转换为同一套训练输入格式；第二个程序负责深度学习训练和评估，即在统一数据集上完成二阶段层级建模、测试评估和模型产物保存。程序运行完成后，系统输出统一数据集文件、训练日志、指标结果、分类报告、混淆矩阵、预测明细和模型权重，为后续课程验收、实验复查和结题报告撰写提供直接依据。

本项目定义的最终分类标签空间为 `NON_ENCRYPTED`、`TLS_FAMILY`、`SSH`、`QUIC`、`VPN`、`TOR`、`I2P`、`FREENET`、`ZERONET` 九类。与传统“网页浏览、聊天、文件传输”等业务分类任务不同，该任务强调识别可见加密机制差异。因而，整个程序系统在设计时围绕“数据异构统一”“弱类样本保留”“层级式深度学习训练”“实验结果标准化输出”四个目标展开。

## 1.2 项目开发背景

本项目最初以加密流量业务类型分类为切入点，但在课程推进过程中，研究目标根据导师要求调整为“加密方法识别”。这一变化带来了两个直接影响：第一，原有数据集和标签体系必须重新梳理，不能再直接沿用旧的业务语义；第二，原有训练脚本需要从任务定义层面重新设计，不能简单在旧脚本上补丁式修改。基于这一背景，项目重新编写了新的数据构建与训练程序，并明确把 `data/Tor/Tor`、`data/NonTor/NonTor` 等原始抓包数据纳入主线研究。

本项目的软件系统名称可定义为“统一加密方法识别深度学习管线”。任务提出者为课程教学要求和项目研究目标调整需求，开发者为项目组两名学生成员，直接用户包括项目组成员本人、课程任课教师以及后续需要基于本项目开展复现实验或撰写课程文档的使用者。系统当前主要面向本地离线研究环境运行，默认工作平台为 Windows，使用 Python 语言实现，依赖 `pandas`、`numpy`、`scikit-learn`、`PyTorch` 以及 `tshark` 等通用工具。

为了保证研究结果可追溯、可复查和可扩展，当前程序系统采用“原始数据目录 + 中间数据目录 + 模型输出目录 + 文档目录 + 工具脚本目录”的组织方式。该设计并不追求上线部署形态，而是优先满足课程项目在中期和结题阶段对实验规范性、结果说明性和文档可维护性的要求。

# 3 程序1（P1-EMD-BUILD）设计说明

## 3.1 程序描述

程序1的实现文件为 `src/encryption_method/build_unified_dataset.py`，其标识符定义为 `P1-EMD-BUILD`。该程序是整个系统的数据入口程序，采用命令行方式运行，属于非常驻内存的离线批处理脚本。程序的设计目标是从多个数据源中提取可用于“加密方法识别”的统一样本表示，并输出规范化的中间数据集。

该程序具有以下特点。第一，它同时处理结构化表格数据和原始抓包数据，是一个典型的异构数据整合程序。第二，它在运行时依赖外部工具 `tshark` 对 PCAP/PCAPNG 文件进行逐包字段抽取，因此兼具 Python 逻辑处理和外部进程协同特征。第三，它不执行模型训练，而是专注于模式一致化、字段对齐、标签统一、样本划分和数据落盘。第四，它允许重复运行，支持在修改过滤规则、标签映射或输入目录后重新生成数据集，因此具备较强的研究迭代价值。

## 3.2 功能

`P1-EMD-BUILD` 的功能可分为五个部分：

1. 读取多个结构化 CSV 数据源，并将不同字段映射为统一数值特征空间。
2. 调用 `tshark` 解析 `data/Tor/Tor` 与 `data/NonTor/NonTor` 下的原始抓包文件，聚合为双向五元组流。
3. 根据协议提示、端口信息和目录语义，为样本分配 `binary_label` 与 `final_label`。
4. 对样本执行 `train/valid/test` 划分，并为每条样本生成 `source_name`、`sample_id`、`sequence_text` 等统一字段。
5. 将结果写出为可直接供训练程序使用的标准化中间文件。

该程序的输入、处理和输出关系可以概括如下表。

| 输入 | 处理 | 输出 |
| --- | --- | --- |
| 多个 CSV 文件 | 字段选择、类型转换、标签映射 | 统一结构化样本 |
| 多个 PCAP/PCAPNG 文件 | `tshark` 抽取、流聚合、协议归一化 | 原始流特征样本 |
| 命令行参数 | 划分比例、最小过滤阈值控制 | 不同实验配置下的数据集 |
| 标签映射规则 | `TLS/DTLS` 归并、`VPN` 归并、`Tor` 过滤 | 最终标签空间一致化 |

## 3.3 性能

程序1的性能要求主要包括正确性、灵活性和时间开销三个方面。

在正确性方面，程序必须保证所有输出样本都遵循统一字段顺序，且数值特征列与元数据描述完全一致；对于无法映射的标签和无法解析的样本，应采取丢弃或警告而不是产生无定义结果。在灵活性方面，程序应支持通过命令行参数调整输入路径、原始抓包目录、输出目录以及抓包流过滤阈值，从而适应不同实验场景。在时间性能方面，结构化 CSV 处理应保持秒级到分钟级完成，原始抓包解析允许存在分钟级开销，但应保证在当前课程项目硬件环境下可接受。基于目前的实际运行经验，`Tor/NonTor` 全量解析属于分钟级任务，整体数据构建可在单机环境中稳定完成。

## 3.6 算法

程序1采用“多源映射 + 原始抓包解析 + 统一字段对齐”的算法思路。

对于结构化数据源，算法首先按预定义字段表读取数据，然后对数值列执行 `to_numeric` 转换，对缺失列补充为空值，对协议字段统一映射为 `TCP/UDP/OTHER`，最后根据来源标签规则映射到统一 `binary_label` 和 `final_label`。例如 `HTTPS` 被映射为 `TLS_FAMILY`，`TLS` 与 `DTLS` 被归并到 `TLS_FAMILY`，`WIREGUARD` 与 `OPENVPN` 被归并到 `VPN`。

对于原始抓包数据，算法通过 `tshark` 提取每个包的时间戳、长度、源地址、目的地址、端口和可见协议列，再使用双向五元组聚合为流。对每条流维护以下核心统计量：

1. `duration = last_time - first_time`
2. `packets_per_second = packet_count / (duration + 1e-9)`
3. `bytes_per_second = byte_count / (duration + 1e-9)`
4. `direction_packet_ratio = fwd_packet_count / (bwd_packet_count + 1.0)`
5. `direction_byte_ratio = fwd_byte_count / (bwd_byte_count + 1.0)`
6. `encrypted_packet_ratio = encrypted_packet_count / packet_count`

同时，程序为每个包生成 `F_LEN_xxxx`、`B_LEN_xxxx` 和 `IAT_xxxxx` 形式的 token，用于后续训练脚本中的轻量序列建模。对于 `RAW_TOR` 样本，程序使用“属于 TCP、存在加密协议提示、端口属于 Tor 常见端口集合或字节数足够大”的保守规则筛选；对于 `RAW_NONTOR` 样本，程序优先根据协议提示和端口号判断 `SSH`、`QUIC`、`TLS_FAMILY`，否则标记为 `NON_ENCRYPTED`。

在样本划分方面，程序采用分层 `train_test_split` 思路，将数据集切分为 `70% train / 15% valid / 15% test`。若样本标签种类不足以分层，则退化为随机划分。最后，程序将所有来源的 DataFrame 统一到完全相同的列顺序后写出。

## 3.7 流程逻辑

程序1的逻辑流程如下：

1. 解析命令行参数并校验输入路径。
2. 定位 `tshark` 可执行文件。
3. 分别构建 `DATASET_CSV`、`BCCC_BINARY`、`BCCC_MULTI`、`FLOW_ALL`、`FLOW_LABELED` 五类结构化数据帧。
4. 递归扫描 `Tor` 与 `NonTor` 原始抓包目录。
5. 对每个抓包调用 `tshark` 抽取字段并聚合流统计量。
6. 为原始流分配标签并补充 `sequence_text`。
7. 对原始流结果执行分层划分。
8. 合并所有来源，生成二分类和多分类两个统一数据集。
9. 统计各来源样本量和各划分标签分布。
10. 将数据集、原始流样本和元数据写出到输出目录。

上述流程的关键判定点包括：输入路径是否存在、原始抓包是否成功解析、流是否满足最小包数和最小字节数过滤条件、标签是否可映射以及是否适合分层划分。

## 3.8 接口

程序1与上层和下层的接口全部通过文件系统和函数调用完成。

上层接口主要是命令行调用接口，调用形式为：

`python src\encryption_method\build_unified_dataset.py --output-dir data\unified_encryption_method_v2_all_data`

下层接口主要包括：

1. 与 `pandas` 的表格读取接口。
2. 与 `scikit-learn` 的数据划分接口。
3. 与 `tshark` 外部进程的字段抽取接口。
4. 与程序2之间的中间文件接口，即 `binary_pretrain.csv`、`multiclass_finetune.csv` 和 `metadata.json`。

接口参数传递方式以文件路径和函数参数为主，不涉及套接字通信、数据库连接或 HTTP API。接口稳定性的关键在于输出字段名不能随意变动，因为程序2直接依赖这些列名。

## 3.9 存储分配

程序1采用内存 DataFrame 与磁盘文件相结合的存储方式。结构化数据读取后首先进入内存 DataFrame，原始抓包解析时以字典形式暂存每个双向流的统计量，待单个抓包处理完成后再转换为 DataFrame。对于全量统一数据集，内存中会同时存在多个来源的数据帧，因此程序运行时需要保证有足够的主存空间支撑 `pandas` 合并与复制操作。

磁盘侧的主要存储分配包括统一数据集 CSV、原始流 CSV 和元数据 JSON。由于不保存原始抓包副本，也不输出中间临时二进制特征缓存，程序1的磁盘占用主要受最终 CSV 文件大小影响，属于研究环境下可接受的中等开销。

## 3.10 注释设计

程序1的注释设计以模块级说明和关键函数命名清晰化为主，不依赖大量冗长内联注释。当前设计中已经包含：

1. 文件头部模块说明，用于说明脚本用途和输出文件含义。
2. 函数级命名注释，例如 `build_raw_capture_rows`、`build_bccc_binary_frame`、`locate_tshark` 等，直接体现职责。
3. 运行日志前缀设计，例如原始抓包解析阶段统一使用 `[raw]` 前缀打印进度和警告。
4. 标签映射与输出字段顺序通过常量区集中定义，减少歧义。

后续若继续扩展 `TOR` 窗口化或更多协议映射规则，建议在新增过滤逻辑与标签规则附近补充简短注释，避免后续维护时难以区分“数据过滤”和“标签推断”的边界。

## 3.11 限制条件

程序1的主要限制条件如下：

1. 运行环境中必须可用 `tshark`，否则原始抓包无法解析。
2. 输入数据的字段名需要与当前脚本中的 `usecols` 和映射规则一致，否则会读取失败。

# 4 程序2（P2-EMD-TRAIN）设计说明

## 4.1 程序描述

程序2的实现文件为 `src/encryption_method/train_hybrid_classifier.py`，其标识符定义为 `P2-EMD-TRAIN`。该程序是整个系统的核心训练与评估程序，采用命令行方式运行，属于非常驻内存的离线深度学习训练脚本。程序的设计目标是在统一数据集上构建一个两阶段层级模型，先识别流量是否加密，再识别其具体加密方法类别，并输出标准化的实验结果文件。

该程序的主要特点如下。第一，它不是单一平面多分类器，而是“二分类预训练 + 多分类微调 + 层级推理”的组合结构。第二，它同时接收数值特征、来源 ID、传输层 ID 和序列 token 输入，属于多分支混合特征深度学习模型。第三，它支持按类别频率进行带权采样与带权损失训练，当前多分类阶段采用平滑反频率补偿。第四，它将模型训练、评估、结果导出和模型保存组织为一个完整闭环，使每次训练运行都能产生可直接写入报告的结构化产物。

## 4.2 功能

`P2-EMD-TRAIN` 的功能可分为六个部分：

1. 读取统一数据集并完成数值特征预处理。
2. 构建词表、来源映射、传输层映射和标签映射。
3. 封装数据集与数据加载器，并根据类别分布生成采样权重。
4. 训练二分类模型并保存最佳检查点。
5. 初始化多分类模型并迁移编码器权重，完成加密方法多分类训练。
6. 在完整测试集上执行层级推理，导出指标、报告、混淆矩阵、预测结果和模型权重。

程序2的输入、处理和输出关系如下表所示。

| 输入 | 处理 | 输出 |
| --- | --- | --- |
| `binary_pretrain.csv` | 二分类数据集封装与训练 | 二分类评估结果 |
| `multiclass_finetune.csv` | 多分类数据集封装与训练 | 多分类评估结果 |
| `metadata.json` | 特征列与标签顺序读取 | 统一训练配置 |
| 训练超参数 | 优化器、采样、损失、早停控制 | 最终模型与日志文件 |
| 二分类最佳权重 | 编码器迁移到多分类模型 | 层级式最终推理结果 |

## 4.3 性能

程序2的性能要求主要包括训练稳定性、弱类可见性和运行效率三个方面。

在训练稳定性方面，程序应在固定随机种子下提供可重复的训练流程，并通过验证集 `Macro-F1` 监控最佳模型。在弱类可见性方面，程序应支持通过采样器和损失函数类别权重缓解类别不平衡问题，避免极小类在训练中完全被忽略。在运行效率方面，程序支持 `cuda` 与 `cpu` 两种设备，其中 GPU 为推荐运行方式；在当前环境下，全量训练属于分钟级任务，能够满足课程项目的实验迭代需求。

根据当前最新实验，程序2已取得如下层级最终测试结果：`Accuracy = 0.9866`，`Macro-F1 = 0.7790`，`Weighted-F1 = 0.9882`。这一结果表明程序2在主流可见加密协议识别方面已经具备较高精度，但在 `TOR` 等弱类上仍有继续提升空间。

## 4.6 算法

程序2采用“两阶段层级混合深度学习算法”。

第一步，数值特征预处理器在 `binary_train` 上拟合中位数、均值和标准差。对于任意输入数值向量 `x`，先执行缺失值中位数填充，再执行对数变换与标准化：

1. `x_fill = fillna(x, median)`
2. `x_log = sign(x_fill) * log1p(abs(x_fill))`
3. `x_norm = (x_log - mean) / std`

第二步，模型将标准化数值特征与缺失掩码拼接后送入数值编码器；同时，对 `source_name` 和 `transport` 分别做嵌入编码；对 `sequence_text` 则先做词表编码，再进入三路一维卷积：

1. `Conv1d(kernel=3)`
2. `Conv1d(kernel=5)`
3. `Conv1d(kernel=7)`

三路卷积特征经最大池化后拼接，与数值特征、来源嵌入和传输层嵌入一起组成融合向量，再送入融合 MLP 得到分类 logits。

第三步，二分类阶段以 `ENCRYPTED` 与 `NON_ENCRYPTED` 为目标训练模型；多分类阶段初始化一个输出维度不同但编码器结构相同的新模型，并通过 `transfer_encoder_weights` 将二分类模型中除最终分类器以外的权重迁移到多分类模型。

第四步，为缓解类别不平衡，程序采用如下带权设计。若第 `c` 类样本数为 `n_c`，总样本数为 `N`，总类别数为 `C`，则基础类别权重定义为：

`w_c = N / (C * n_c)`

然后对其施加幂次平滑：

`w'_c = (w_c)^p`

其中 `p` 为 `sampler_power` 或 `class_weight_power`。当前多分类阶段使用 `p = 0.5`，即温和反频率补偿。

第五步，在最终推理时执行层级判定：

1. 若二分类模型预测为 `NON_ENCRYPTED`，则最终输出 `NON_ENCRYPTED`。
2. 若二分类模型预测为 `ENCRYPTED`，则将该样本送入多分类模型，在八个加密方法类别中做细粒度判定。

## 4.7 流程逻辑

程序2的逻辑流程如下：

1. 解析命令行参数并设置随机种子。
2. 读取统一数据集文件和元数据文件。
3. 按 `split` 字段构造训练集、验证集和测试集。
4. 在二分类训练集上拟合数值预处理器。
5. 根据训练文本构建词表，根据全量数据构建来源映射和传输层映射。
6. 构建二分类与多分类 `HybridDataset`。
7. 基于类别频率生成带权采样器与类别权重。
8. 训练二分类模型，并按验证集 `Macro-F1` 保存最佳状态。
9. 评估二分类模型并导出二分类报告。
10. 初始化多分类模型，迁移编码器权重。
11. 训练多分类模型，并按验证集 `Macro-F1` 保存最佳状态。
12. 评估多分类模型并导出多分类报告。
13. 以二分类预测作为门控，在完整测试集上执行层级最终推理。
14. 导出 `metrics.json`、模型文件、历史文件和各类报告文件。

## 4.13 尚未解决的问题

程序2当前尚未完全解决的问题主要包括：

1. `TOR` 召回率仍然偏低，说明当前数据与模型组合对该弱类覆盖不足。
2. `FREENET` 精确率仍较低，类别边界存在过度吸引现象。

4. 尚未系统补做按抓包文件或按来源隔离的更严格泛化验证。

总体而言，程序2已经具备完整可用的训练、评估和结果导出能力，但仍需要依赖后续数据增强和实验规范补强，才能在弱类和跨源场景下达到更稳健的最终表现。
