# 网络加密数据流识别与分类技术研究（课程项目方案）

## 1. 研究背景与意义
随着 HTTPS、TLS 1.3、QUIC 等协议广泛部署，传统基于载荷内容的检测方法有效性下降。  
在不解密业务内容的前提下，通过流量统计特征与握手元数据实现分类，是网络安全监测、异常行为识别与流量治理的重要方向。

本项目聚焦“加密流量应用类型识别”，目标是在学术合规和隐私保护前提下，构建一套可复现实验流程，并验证机器学习方法在该任务上的可行性与局限性。

## 2. 研究目标与研究问题
### 2.1 总体目标
构建一个面向加密流量的分类系统，实现对应用类别的自动识别（如网页浏览、视频流媒体、文件传输、即时通信等）。

### 2.2 具体研究问题
1. 在不解密载荷的条件下，哪些流统计特征对分类最有效？
2. 传统机器学习模型（RF/SVM/KNN）在该任务上的性能差异如何？
3. 当面对类别不平衡、跨时间采集等场景时，模型鲁棒性如何变化？
4. 握手特征（如 SNI/JA3）与纯统计特征相比，增益有多大？

### 2.3 可量化目标
1. `Macro-F1 >= 0.85`（多分类主指标）。
2. 关键类别（视频流、网页、文件传输）召回率 `>= 0.80`。
3. 输出可解释结果（特征重要性、混淆矩阵、错误案例分析）。

## 3. 研究范围与合规边界
1. 仅研究“流量分类”，不进行任何解密、破解、绕过认证等行为。
2. 仅使用公开数据集或团队自行采集的授权数据。
3. 报告中明确数据来源、采集条件和隐私处理措施（脱敏、匿名化）。

## 4. 技术路线
1. 流量采集与样本构建：公开数据集 + 可选自采数据。
2. 流切分与特征提取：基于五元组生成流，提取统计特征与握手特征。
3. 特征工程：清洗、标准化、相关性筛选、降维/选择。
4. 模型训练与调参：建立基线与主模型，进行交叉验证。
5. 评估与解释：输出分类指标、可视化和错误分析。
6. 复现与部署演示：提供脚本化流水线，可选实时分类 Demo。

## 5. 数据方案
### 5.1 数据来源
1. 公开数据集（推荐优先）：
   - `ISCX VPN-nonVPN`
   - `CIC-IDS-2017`（筛选与任务相关流量）
2. 自主采集（可选进阶）：
   - 使用 Wireshark/tcpdump 在校园网或实验网采集授权流量。
   - 采集场景需覆盖至少 4 类应用。

### 5.2 数据预处理
1. 按五元组（源/目的 IP、源/目的端口、协议）进行 Flow 切分。
2. 清洗异常值与缺失值，剔除明显泄漏标签字段（如时间戳绝对值、IP 明文字段）。
3. 统一标签体系，处理类别不平衡（欠采样/过采样/类别权重）。
4. 划分训练集、验证集、测试集（建议 `6:2:2` 或 `7:1:2`）。

### 5.3 特征设计
1. 基础统计特征：
   - Flow Duration、Fwd/Bwd 包数、包长均值/方差、IAT 统计量。
2. 方向与时序特征：
   - 上下行字节比、前 N 包长度序列统计、突发性特征。
3. 握手相关特征（可选）：
   - TLS 版本、Cipher Suites 数量、SNI 长度、JA3 指纹。

## 6. 模型与实验设计
### 6.1 模型设置
1. 基线模型：Decision Tree。
2. 主模型：Random Forest。
3. 对比模型：SVM、KNN（可按算力二选一或全做）。
4. 可选拓展：XGBoost/LightGBM（作为性能上限参考）。

### 6.2 训练与调参
1. 使用 `Stratified K-Fold`（建议 `k=5`）进行交叉验证。
2. 网格搜索或随机搜索调参（如树深、树数量、C、gamma、邻居数）。
3. 固定随机种子并记录实验配置，保证可复现性。

### 6.3 对比实验（建议至少 3 组）
1. 仅统计特征 vs 统计 + 握手特征。
2. 不处理类别不平衡 vs 使用类别权重/采样策略。
3. 单一数据源训练测试 vs 跨场景/跨时间测试（验证泛化）。

## 7. 评价指标与结果展示
### 7.1 评价指标
1. Accuracy（辅助指标）
2. Precision / Recall / F1-Score（重点）
3. Macro-F1、Weighted-F1（多分类核心指标）
4. 训练时间与推理时延（工程可用性指标）

### 7.2 可视化与分析
1. 混淆矩阵：定位易混淆类别。
2. ROC/PR 曲线（按需选择）。
3. 特征重要性排名（RF/XGBoost）。
4. 错误样本案例分析（至少 3 类典型误判）。

## 8. 项目分工建议
1. 数据组：数据获取、抓包脚本、清洗与标签整理。
2. 特征组：特征提取、特征选择、统计可视化。
3. 算法组：模型训练、调参、实验对比与结果复现。
4. 文档组：周报汇总、论文式报告撰写、答辩 PPT 与演示脚本。

说明：每个组至少指定 1 名“备份负责人”，避免单点延误。

## 9. 进度规划（7 周）
1. 第 1 周：文献调研、任务分解、环境搭建、数据源确认。
2. 第 2 周：数据下载/采集、流切分、初步特征提取。
3. 第 3 周：完成数据清洗与标签统一，输出可训练数据集。
4. 第 4 周：实现基线模型与主模型，完成第一版结果。
5. 第 5 周：调参与消融/对比实验，补齐可视化结果。
6. 第 6 周：泛化测试、误差分析、整理结论与局限。
7. 第 7 周：完善报告、PPT 与演示，完成项目验收。

## 10. 风险与应对
1. 数据标签质量不足：先做小规模人工抽样校验，再批处理。
2. 类别不平衡严重：引入类别权重 + 分层采样 + 宏平均指标。
3. 模型过拟合：交叉验证、特征筛选、限制模型复杂度。
4. 进度滞后：设置每周里程碑与最低交付标准（MVP）。

## 11. 预期交付物
1. 源代码仓库：含数据处理、训练、评估、可视化脚本及 `README` 运行说明。
2. 数据与特征文件：清洗后数据（CSV/Parquet）与字段说明文档。
3. 实验报告：背景、方法、实验设置、结果、误差分析、结论与展望。
4. 答辩材料：PPT + 演示视频/现场演示脚本。
5. 附录：实验参数表、依赖环境清单、复现实验步骤。

## 12. 评分导向建议（冲高分）
1. 结构完整：研究问题-方法-实验-结论逻辑闭环。
2. 结果可信：有对比实验、消融实验和误差分析，而非只给最高分数。
3. 工程规范：代码可运行、目录清晰、实验可复现。
4. 展示清晰：图表可读、结论可解释、能回答“为什么有效/为什么失效”。
